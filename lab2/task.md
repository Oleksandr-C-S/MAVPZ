# Завдання 2 — Вимоги та Use Cases

## Мета

Структурувати вимоги, описати сценарії використання та забезпечити трасування між вимогами і Use Cases.

## Артефакт

Робота повинна містити:
- EARS-вимоги;
- user stories, інтегровані безпосередньо в Gherkin-сценарії (без окремого файла `user-stories.md`);
- Gherkin-сценарії (Given/When/Then), щонайменше 3 для складнішого UC-02;
- окремий блок вимірюваних NFR у `requirements.md`;
- матрицю трасування `вимога-id ↔ сценарій/UC`;
- Use Case Diagram у PlantUML;
- рендер діаграми.

## Що потрібно зробити

1. У `spec.md` описати щонайменше два типи акторів: людину та зовнішню систему/сервіс.
2. Визначити головні цілі акторів.
3. Написати вимоги у форматі EARS.
4. Описати потреби користувача разом із Gherkin-сценаріями в `gherkin.md`, без окремого `user-stories.md`.
5. Написати щонайменше три Gherkin-сценарії для UC-02 у форматі Given/When/Then та додати NFR з числовими межами у `requirements.md`.
6. Побудувати Use Case Diagram з `include`, `extend` та узагальненням.
7. Побудувати матрицю трасування функціональних вимог із реальними зв'язками багато-до-багатьох; NFR до неї не включати.
8. Позначити щонайменше одну непокриту вимогу та пояснити її.
9. Провести аудит EARS, include/extend та узгодженості з ER-моделлю Завдання 1.
10. Зафіксувати топ-3 розбіжності та виправити їх окремими комітами.
11. Підготувати ADR та `DEFENSE.md`.

## Ознаки відмінного виконання

- EARS-вимоги однозначні й тестовані;
- трасування реально багато-до-багатьох;
- актори та сценарії узгоджені з моделлю даних Завдання 1;
- є щонайменше одна непокрита вимога з поясненням;
- `include`, `extend` та узагальнення використані за змістом.

## Уточнення викладача від 23.10.2026

Вимоги та сценарії подаються в `gherkin.md` без окремого файла User Stories. NFR мають бути вимірюваними і знаходитися в `requirements.md`, але не входити до Use Case Diagram або матриці функціонального трасування.
