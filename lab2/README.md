# Lab 2 — Вимоги та Use Cases

## Домен

Друга лабораторна продовжує домен із Завдання 1 — систему бронювання навчальних аудиторій університету.

ER-модель з Lab1 містить:
- User;
- Building;
- Room;
- Booking;
- BookingStatus;
- Equipment;
- RoomEquipment.

У цій роботі я переходжу від структури даних до вимог і сценаріїв використання системи.

## Основні актори

Люди:
- Студент;
- Викладач.

Узагальнений актор:
- Користувач.

Зовнішня система:
- Сервіс автентифікації університету.

## Основні цілі

Користувач повинен мати можливість:
- переглядати доступні аудиторії;
- фільтрувати їх за обладнанням;
- створювати бронювання;
- скасовувати власні бронювання;
- переглядати власні бронювання.

Сервіс автентифікації використовується для підтвердження особи перед операціями, які змінюють або показують персональні дані.

## Зв'язок з Lab1

Use Cases використовують сутності з ER-моделі:
- User — ідентифікація власника бронювання;
- Room — вибір аудиторії;
- Booking — створення, перегляд і скасування;
- BookingStatus — перевірка, чи бронювання блокує аудиторію;
- Equipment та RoomEquipment — фільтрація аудиторій за обладнанням.
