Сценарії описують систему бронювання навчальних аудиторій. Умови про статуси узгоджені з ER-моделлю Lab1: доступність залежить від `BookingStatus.blocks_room`.

## SC-01 — Пошук доступних аудиторій

```gherkin
Feature: Пошук доступних аудиторій

  Scenario: Знайдено аудиторії без конфлікту бронювань
    Given користувач задав часовий інтервал і мінімальну місткість
    And у системі є аудиторії, що відповідають заданій місткості
    When користувач запускає пошук
    Then система показує аудиторії потрібної місткості
    And жодна показана аудиторія не має бронювання зі статусом blocks_room = true, що перетинається з вибраним інтервалом
```

Пов'язані вимоги: REQ-01, REQ-03.  
Use Cases: UC-01, UC-07.

## SC-02 — Успішне створення бронювання

```gherkin
Feature: Створення бронювання

  Scenario: Користувач бронює доступну аудиторію
    Given користувач успішно пройшов автентифікацію
    And вибрана аудиторія доступна у заданий часовий інтервал
    When користувач підтверджує бронювання
    Then система створює Booking для поточного User і вибраної Room
    And зберігає час початку та завершення бронювання
```

Пов'язані вимоги: REQ-02, REQ-03.  
Use Cases: UC-02, UC-06, UC-07.

## SC-03 — Відхилення бронювання через конфлікт

```gherkin
Feature: Перевірка доступності

  Scenario: Аудиторія вже заброньована на той самий час
    Given для аудиторії існує Booking зі статусом blocks_room = true
    And часовий інтервал нового бронювання перетинається з існуючим
    When користувач намагається створити нове бронювання
    Then система відхиляє створення нового Booking
    And повідомляє, що аудиторія недоступна в цей час
```

Пов'язана вимога: REQ-03.  
Use Cases: UC-02, UC-07.

## SC-04 — Фільтрація за обладнанням

```gherkin
Feature: Фільтрація аудиторій

  Scenario: Користувач шукає аудиторію з проектором
    Given користувач відкрив список доступних аудиторій
    And у системі існує тип обладнання Projector
    When користувач застосовує фільтр Projector
    Then система показує тільки доступні аудиторії з відповідним RoomEquipment
    And кількість Projector у цих аудиторіях більша за нуль
```

Пов'язані вимоги: REQ-01, REQ-05.  
Use Cases: UC-01, UC-05.

## SC-05 — Скасування власного бронювання

```gherkin
Feature: Скасування бронювання

  Scenario: Користувач скасовує своє бронювання
    Given користувач успішно пройшов автентифікацію
    And обране бронювання належить поточному User
    When користувач підтверджує скасування
    Then система встановлює статус Booking у Cancelled
    And статус Cancelled має blocks_room = false
```

Пов'язана вимога: REQ-04.  
Use Cases: UC-03, UC-06.

## SC-06 — Перегляд власних бронювань

```gherkin
Feature: Мої бронювання

  Scenario: Користувач переглядає свої бронювання
    Given користувач успішно пройшов автентифікацію
    When користувач відкриває розділ Мої бронювання
    Then система показує лише Booking з user_id поточного User
```

Пов'язана вимога: REQ-06.  
Use Cases: UC-04, UC-06.
