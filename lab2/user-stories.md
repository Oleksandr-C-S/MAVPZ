# User Stories — Завдання 2

## US-01 — Пошук доступної аудиторії

**Як** студент або викладач, **я хочу** переглянути аудиторії, доступні на обраний час, **щоб** знайти приміщення для заняття.

Критерії прийняття:
- користувач задає початок, кінець і мінімальну місткість;
- система показує лише аудиторії, де немає конфліктного бронювання зі статусом `blocks_room = true`;
- час початку має бути раніше часу завершення.

Пов'язані вимоги: REQ-01, REQ-03. Use Cases: UC-01, UC-07.

## US-02 — Створення бронювання

**Як** авторизований користувач, **я хочу** забронювати вільну аудиторію, **щоб** користуватися нею у визначений час.

Критерії прийняття:
- особу користувача підтверджено зовнішнім сервісом;
- перед створенням бронювання система ще раз перевіряє доступність;
- новий `Booking` пов'язаний з поточним `User` і вибраною `Room`;
- за наявності конфлікту бронювання не створюється.

Пов'язані вимоги: REQ-02, REQ-03. Use Cases: UC-02, UC-06, UC-07.

## US-03 — Фільтрація за обладнанням

**Як** користувач, **я хочу** відфільтрувати аудиторії за необхідним обладнанням, **щоб** не переглядати невідповідні приміщення.

Критерії прийняття:
- фільтр є необов'язковим для пошуку;
- система використовує `Equipment` і `RoomEquipment`;
- показуються аудиторії, у яких кількість потрібного обладнання більша нуля.

Пов'язані вимоги: REQ-01, REQ-05. Use Cases: UC-01, UC-05.

## US-04 — Скасування власного бронювання

**Як** авторизований користувач, **я хочу** скасувати своє бронювання, **щоб** звільнити аудиторію для інших.

Критерії прийняття:
- користувач може скасувати лише власне бронювання;
- статус змінюється на `Cancelled`;
- статус `Cancelled` має `blocks_room = false`.

Пов'язані вимоги: REQ-04. Use Cases: UC-03, UC-06.

## US-05 — Перегляд власних бронювань

**Як** авторизований користувач, **я хочу** переглядати свої бронювання, **щоб** бачити заплановані та скасовані заняття.

Критерії прийняття:
- показуються лише записи `Booking` з `user_id` поточного користувача;
- чужі бронювання не відображаються в особистому списку.

Пов'язані вимоги: REQ-06. Use Cases: UC-04, UC-06.

## Відкладена функція

Нагадування за 15 хвилин до бронювання (REQ-07) поки не має User Story, реалізованого Use Case або Gherkin-сценарію. Це свідомо непокрита вимога, яку планується опрацювати після визначення механізму сповіщень.
