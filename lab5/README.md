## Що зроблено

У лабораторній побудовано UML Component Diagram у PlantUML для системи бронювання аудиторій. Модель показує основні компоненти, інтерфейси між ними, залежності, межу системи та зовнішню інтеграцію з університетським сервісом автентифікації.

Основний приклад для архітектури — **UC-02 «Створити бронювання»** із Завдання 2. Перед збереженням бронювання потрібно повторно перевірити доступність аудиторії, щоб уникнути конфліктних записів.

## Склад архітектури

- **Web UI** — взаємодія зі студентом або викладачем.
- **Booking API** — приймання запитів і передача їх до сервісу.
- **BookingService** — координація сценарію бронювання.
- **AvailabilityService** — попередня перевірка доступності аудиторії.
- **AuthenticationAdapter** — звернення до зовнішнього університетського сервісу автентифікації.
- **BookingRepository** — робота з бронюваннями та атомарна фінальна перевірка конфліктів під час створення запису.
- **RoomRepository** — доступ до даних про аудиторії.
- **Booking Database** — збереження `User`, `Building`, `Room`, `Booking`, `BookingStatus`, `Equipment`, `RoomEquipment`.

Університетський сервіс автентифікації розміщено **за межею системи**. Зв'язки між компонентами описані через окремі provided/required інтерфейси: `IBookingApi`, `IBookingService`, `IAvailabilityService`, `IAuthentication`, `IBookingRepository`, `IRoomRepository`.
